🌐 Connection how requests reach PressReader

    

      

        ⚠️
        

          PressReader's API does not send CORS headers, so a browser cannot call it directly.
          We checked: api.prod.pressreader.com answers no preflight and returns no
          Access-Control-Allow-Origin, so your browser blocks the request before it is even sent —
          no matter how valid your key is. Nothing in this page can override that; it is a browser security rule.
          


          This published app is already configured with its own restricted proxy. Each visitor
          uses their own PressReader API key. The connection test below confirms that the proxy and key work.
          If you would rather not send the key through this site's Worker, the
          companion Colab notebook
          calls the API from Python, where CORS does not apply at all — then drag the .db it produces
          onto the Database tab here to use the browsing and export tools.
        

      


      

        
        
        
Default: 

      


      

        
        
        

          Your request is sent through this site's Cloudflare Worker only to reach PressReader.
          The Worker does not log, store, cache, or place your API key in a URL. Each visitor supplies
          their own PressReader key. You may configure your own compatible proxy if you prefer.

        Run it on your own machine instead — no account, no signup
        

          

            proxy/local-proxy.py is a single Python file that needs nothing but a standard
            Python 3 install. Run python3 local-proxy.py, then put
            http://127.0.0.1:8787 in the Proxy URL box above. Your key never leaves your computer.
          

          

            ⚠️
            

              Serve this page locally too. Current Chrome blocks a page loaded over public
              HTTPS from reaching a loopback address — “Permission was denied for this request to access
              the loopback address space” — so a local proxy will not work with the hosted
              copy of this app. Download the repository and run
              python3 -m http.server 8000, then use the app at
              http://localhost:8000. Both sides are then in the same address space and the block
              does not apply. To use the hosted copy, deploy the Cloudflare Worker instead: it has a public
              HTTPS address.
            

          

          

            It binds to 127.0.0.1 only, so nothing else on your network can reach it, and it does
            not log requests. The trade-off: it has to be running each time you use the app, and you cannot
            share it with a colleague.

🔐 What happens to your data

    

      

        
Your key

        
Held in this tab. Written to localStorage only if you tick "Remember this key", and removable with the Clear button. It is attached to API requests and to nothing else, and is never written into an export.

        
Your articles

        
Stored in a SQLite database inside your browser (IndexedDB). No copy is sent anywhere.

        
This page

        
Static files on GitHub Pages. No analytics, no cookies, no account, no server-side code.

        
Third-party code

        
No code loads from a third-party CDN. The pinned sql.js JavaScript and WebAssembly files are bundled with this site and run entirely in this tab. Every export format — Excel included — is written by this app's own code.

        
Clearing site data

        
Erases the database. Download the .db file if you want to keep it.

      

    

  


  

    
🩺 Troubleshooting

    

      

        "Failed to fetch" or "Network error" the moment I search
        

          
If you have no proxy configured, this is expected and is not a fault in your key — PressReader
          sends no CORS headers, so the browser refuses the request. Set up the proxy above.

          
If you do have a proxy configured: check the address is exactly right, that the proxy is
          deployed and awake, and that its ALLOWED_ORIGIN setting contains this page's address
          (this origin). Then run the connection test.

          
Serving the page from python -m http.server does not fix this. A local
          server changes your page's address but has nothing to do with the request to PressReader, which still
          gets blocked. You need it to load this app from your own machine at all — ES modules will not run over
          file:// — but it does nothing for the API call.

        

      

      

        “Permission was denied … to access the loopback address space”
        

          
You pointed the hosted (HTTPS) copy of this app at a proxy on 127.0.0.1. Chrome does
          not allow that. Either run this app locally as well (python3 -m http.server 8000, then
          open http://localhost:8000), or deploy the Cloudflare Worker, which has a public HTTPS
          address and works from anywhere.

        

      

      

        401 or 403 from the API
        

          
The key was rejected. Check for a stray space or a partial paste, confirm the key is active in your
          PressReader developer account, and confirm your plan includes the Discovery search endpoint.

        

      

      

        429 — too many requests
        

          
You hit a rate limit. Lower "Articles to fetch", wait a few minutes, and try again. The app already
          pauses between pages, and it stops paging as soon as the API reports no further results.

        

      

      

        PressReader has an article, but my search does not find it
        

          
Open Advanced options, enable Debug this search, and run it again.
          The report shows the exact body sent to PressReader, its reported total, every returned title,
          and anything the collector skipped. If the article is absent from api.pages[].items,
          the Discovery API did not return it—the collector did not remove it.

          
Try the headline as an exact quoted phrase, Headlines only, country
          US, and a narrow date range. PressReader's reading site and Discovery search index
          can behave differently.

        

      

      

        The search works but every field is empty
        

          
Open Advanced options, enable Debug this search, and run it again.
          The key-safe report shows the returned IDs, titles, publications, dates, pages and links without
          retaining article text or the untouched API response.

        

      

      

        Excel opens my CSV with mangled accents
        

          
Keep "Add a UTF-8 byte-order mark" ticked, or export .xlsx instead — that format carries
          its encoding internally and never suffers from this.

        

      

      

        My database vanished
        

          
Browser storage is per-site and per-profile, and private/incognito windows discard it on close.
          Some browsers also evict storage from sites you rarely visit. Download the .db file for
          anything you want to keep, and import it again later.
